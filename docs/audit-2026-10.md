## 1. 反映・同期（R）— 「変えたのにリロードしないと出ない」

### 1.1 なぜ起きるか（設計上の根っこ）

利用者の一番の不満はここにある。個々の漏れの前に、原因の構造を書く。

1. **シェルのローダー1つが、性質の違う4つのデータを抱えている。**
   - 抱えているもの: 会話一覧・ボット・フォルダ・設定。
   - パスが変わる遷移では取り直さない（`shell.tsx:138-145`）。
   - 「鮮度の印」は会話一覧の分しか無い（`MAX(updated_at)` と `list_version`）。ボットと設定には「変わった」と知る手段が同じタブにも他端末にも無い。
2. **書き込みの後片付けが、呼ぶ側ごとの手書き。**
   - 書き込みは素の `fetch` で、action / fetcher を通らない。
   - そのため revalidate・`invalidateChat`・`applySettings` を毎回手で書いている。書き忘れがそのまま反映漏れになる。
3. **ローダーの値を `useState(初期値)` に写して、以後追従しない部品が多い。**
   - 該当: Chat の model・params・bot・prompt、Images、Settings。
   - 取り直しても結果が捨てられる経路がある。
4. **会話そのものに版が無い。**
   - `updated_at` が「一覧での並び」と「中身の鮮度」を兼ねている。
   - 並びを動かしたくない変更（枝・設定・削除・区切り）が、鮮度の判定から漏れる。
5. **取り直しの合図が `visibilitychange` だけ。**
   - iPhone 向けの作り。Mac の「隠れずに戻る」や、2つのウィンドウを並べる使い方を拾えない。
6. **ビルドの版を突き合わせていない。** 遅延チャンクの失敗も「次に取り直す」で済ませている。

**R-1 の現象**

- 新しいボットを保存して一覧へ戻ると、「ボットはまだありません」のまま。
- 既存のボットを直しても、一覧は古いまま。そこで「複製」を押すと**古い内容で複製**される。
- 入力欄のモデル一覧・ホームのランチャー・`@ボット名` で選ぶと、**編集前のモデル・システムプロンプト・パラメータで生成**する。
- 直るのは、再読み込みするか、会話一覧の何かが動いたときだけ。

**R-2 の現象**

- Mac で会話を開いたまま、iPhone で同じ会話を進める。Mac のサイドバーはその会話を上へ上げるが、会話画面は古いまま。
- そこで Mac から送ると、古い葉に繋がる。iPhone 側のやり取りは兄弟の枝に回り、モデルにも渡らない。

## 7. まとめて直すなら（反映と同期の土台）

R の個別の手当てより、次の5つを入れるほうが漏れが根本から減る。

**A. 版の表を1つにして、既にある5秒の往復で配る**

- `meta` に `list_version`（既存）・`bots_version`・`settings_version` を置く。各書き込みと同じ batch で進める（サブリクエストは増えない）。
- 会話の行に `rev` を足し、`updated_at` を動かさない変更でも進める。
- `/api/conversations/unread` から `{botsVersion, settingsVersion, buildId}` も返す。
- クライアントは変わった部分だけを取り直す。開いている会話の `rev` か生成中が変わったら、`syncFeed` と設定の差し替えを呼ぶ。
- 片づくもの: R-1〜R-4・R-7・R-15。

**B. 書き込みの入口を1つにする**

- 形の例: `mutate({url, init, optimistic, touches: ["list"|"bots"|"settings"|{conv}]})`。
- 楽観表示・失敗の巻き戻しと通知・成功時の取り直しを、1か所に置く（サイドバーの `sendOptimistic` を一般化したもの）。
- BroadcastChannel で同じ端末の他のタブへすぐ配る。
- 片づくもの: R-9・R-16・U-1 の一部・K-6。

**C. 写した state をローダーへ追従させる**

- Images・Settings は loaderData を正にし、手元の追加分だけを重ねる。
- Chat の会話の設定は、`rev` が変わったら差し替える。

**D. 戻ってきたときの合図を広げる**

- `focus`（間引き付き）を足す。
- デスクトップに「取り直す」ボタンを置く。
- storage イベントで見た目を貼り直す。

**E. 遅延チャンクの失敗は1回だけ再読み込みする**（R-7）
