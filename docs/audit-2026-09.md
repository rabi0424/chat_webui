# 全面監査（2026-09）

対象: `main`（#71 取り込み後）。サーバー・クライアント・二次画面と設定・
テスト品質・iPhone 幅でのデザインの5つの観点で、コードを読み、本物の
SQLite と黙ったままの上流を立てて動かし、iPhone 15 相当の画面を
ライト／ダークで撮って見た。

ID の接頭辞: **S** サーバー、**C** クライアント、**P** 二次画面と設定、
**T** テスト、**D** デザイン。コミットメッセージにも同じ ID を添えてある。

## 未対応のもの（次にやるなら上から）

1. **S-6 / P-4: 実行体の時間の台帳を1つにする。** 単発・司令役・担当が
   開始と終了で同じ表（`do_ledger(at, ms)`）に書き、`DAILY_DO_MS_SQL` は
   その表だけを足す。使用量の画面に「今日の実行体の時間 / 上限」の帯を
   出す。画像モデルを普通に使うだけで枠の外で消費が積もる現状は、
   締め出しを防ぐという目的に届いていない。
2. **C-3: 上方の伸縮でスクロール位置が跳ぶ。** `MessageList` に
   `ResizeObserver` を張り、変化した要素が読み位置より上なら `scrollTop`
   を差分だけ動かす小さなフックを置く。Δ の計算だけを純関数にして検査。
   画像には `aspect-ratio` を予約する。
3. **P-7: 画像一覧のカーソルを `(created_at, id)` の複合に。** Runware の
   複数枚は同じ ms で作られるので、ページ境界で2枚目以降が永久に出ない。
   `tests/schema.test.ts` の一覧の検査は時刻がすべて別で、これを通す。
4. **C-7: 2通目以降が落ち着いたら `navigate(replace)` で現在地を合わせる。**
5. **P-13: `updateAppSettings` の入力検査を純関数に切り出す**（`clampPageSettings`
   と同じ形）。null/true/配列を弾き、NumberInput は範囲外を打ったとき欄も
   丸める。
6. **C-11: 先読みキャッシュを「離れるときに最新で置き直す」に反転。**
7. **C-13: 詳細ポップオーバーに Escape と role、確認の初期フォーカスと戻し。**
8. C-8、C-14、P-9、P-14、D-10（項目の区切り）、D-12（角丸のトークン化）、
   D-15（root の ErrorBoundary を RouteError の部品で）。

## テストの弱点（監査 T）

- **T-3** 設定の DOM テストは fetch を同期で返すので順序の問題を検出できない。
  `settings-save-order.test.tsx` を足したが、他の4本は据え置き。
- **T-4** `settings-page-limits` は `patches.at(-1)` だけ。全 patch 列を見る。
- **T-5** 画像一覧の schema テストは時刻がすべて別（P-7 の前提）。
- **T-6** `readUsageOverview` の batch の添字割り当てはどのテストも通らない。
  計画と割り当てを純関数に。
- **T-7** 配線テスト（`toContain` で文字列）は識別子がコメントに残るだけで通る。
  CSP は `entry.server` を実際に描いて突き合わせるほうが強い。
- **T-8** 画像一覧の続き読み・カーソル・`IMAGES_PAGE_SIZE` の結び付きが未検査
  （IntersectionObserver が no-op）。
- **T-10** bots / images の fetch スタブが常に 200（失敗経路の空白。P-6 の
  分だけ足した）。
- **T-11** 使用量の verdict を手で作って渡している（loader の配線が未検証）。
- ポーリングの時間による諦め（10分）は実時間を要するので検査していない。
  待ちの計算（`pollBackoffMs`）だけを純関数として見ている。

## デザイン（監査 D）

撮った画面: iPhone 15 相当（393×852・3x・touch）ライト／ダーク各 26 枚、
デスクトップ 20 枚。土台（意味トークン・touch 変種・safe-area・
`--app-height`・reduced-motion・focus ring）は商用品質で、届いていない
理由は5つだった——Markdown の組版、設定の行の崩れ、面の作り、画面ごとの
不揃い、指の操作。上の4つのコミットで当てたのは表のとおり。

残りの提案:

- **角丸と影の段を `@theme` に置く**（D-12）。いまは 2/3/6/7/10/13/22px と
  rem 指定が混在。xs 6（バッジ）・sm 10（欄・チップ）・md 14（カード・
  コード）・lg 18（設定の塊・ポップオーバー）・xl 22（シート・吹き出し）の
  5段に寄せ、影は「浮く」「貼り付く」の2段だけにする。
- **設定画面の地を `bg-sunken` に**して白いカードを載せると iOS の grouped
  スタイルにより近くなる（いまは白地に薄い枠）。
- **ポップオーバーの下に薄い scrim**（`bg-black/10`）を敷くと、開いている
  ことが指で分かりやすい。
- 会話の中のコードブロックは 13px 固定でよい（本文の倍率に引きずられて
  長い行がさらに折れる）。

## 新機能の提案

実装はしていない。効きそうな順。

1. **実行体の時間の残量表示**（S-6 と一体）。使用量の画面に「今日
   4,200 / 90,000 秒」の帯。締め出しは通知メールが来るまで気づけない
   ので、これだけは自分で見えていたい。
2. **会話の書き出し**（Markdown 1本）。バックアップは D1 の export だけで、
   1つの会話を人に渡す・別の場所に貼る手段が無い。表示中のパスを
   `# タイトル` + 発言ごとの見出しで出すだけなら、サーバーは
   `/api/conversations/:id/full` があるのでクライアントだけで済む。
3. **応答の中の画像をまとめて保存**（複数選択して `a[download]`）。
   「成功するまで生成」で積まれた 10 枚を1枚ずつ開いて保存している。
4. **下書きの同期**。下書きは端末ごと（localStorage）なので、Mac で書き
   かけて iPhone で続きが打てない。会話ごとに `meta` へ持てば D1 の
   1行で済む（打つたびではなく、画面を離れるときに書く）。
5. **「読み上げ」の live region を拡張して、生成完了をホーム画面の
   バッジに**（PWA の `navigator.setAppBadge`）。未読の印はサイドバーに
   あるが、アプリを閉じていると分からない。Service Worker は要件外なので
   開いているあいだだけになるが、別の会話を見ているときには効く。
6. **モデルの「お気に入り」**。モデル一覧は数百件で、最近使った順の
   上に固定できるものが欲しい。`recent-models.ts` の隣に `pinned` を
   持つだけ。
